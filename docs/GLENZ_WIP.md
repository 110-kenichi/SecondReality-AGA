### 0.1 診断モード (`M2_GLENZ_DIAG`, ビットの和)

| bit | 値 | 内容 |
|----|----|------|
| 0 | 1 | 全面を同じ色 (15=緑) で**上書き**して形だけ見る (XOR なし) |
| 2 | 4 | **タイムラインを止める** (同じフレームで A/B するため) |
| 3 | 8 | 小さい方 (demo_glz) を描かない |
| 4 | 16 | 大きい方 (demo_glz2) を描かない |
| 5 | 32 | 1..14 番をビット色にする (使われた index の確認用) |
| 6 | 64 | 左上に diag 値・frame・VBL×4 (4=50fps) を色/バーで出す |

(bit 1 は以前の「色 0 のスパンを緑で塗る」用。輪郭補正を外したので未使用。)

A/B の例 (frame 1000 で固定):
```powershell
$env:M2_GLENZ_FRAME=1000; $env:M2_GLENZ_DIAG=13  # 大だけ・全面緑 = 三角形の和
$env:M2_GLENZ_FRAME=1000; $env:M2_GLENZ_DIAG=12  # 大だけ・通常色
python run/analyze-glz.py --truth run/z1300.png --target run/z1200.png
```


## 1. オリジナルの描画 (解析結果)

出典: `reference/SecondReality/GLENZ/{MAIN.C,VEC.ASM,NEW.ASM,VIDPOLY.ASM}`

### 1.1 面の生成 (`MAIN.C`)
- 14 点 = 立方体 8 (±100*50) + 軸方向のトゲ 6 (±170*50)。
  2 個目 `pointsb` は ±60*99 / ±105*99。
- 面は `epolys` / `epolysb` の 24 三角形。色ワードは `0x4000 | base`
  (base = 0x02,0x04,...,0x30)。
- `cmatrix_yxz` → `csetmatrix` → `crotlist` の 2 段 (回転 → スケール+平行移動)。
- 投影: `sx = x*256/z + 160`, `sy = y*213/z + 130`, `projminz = 128`。

### 1.2 表裏の判定 (`checkhiddenbx`, VEC.ASM)
```
cross = (x0-x1)*(y0-y2) - (y0-y1)*(x0-x2)     ← 2 項目は y0-y1 !!
cross < 0 → hidden (carry set)
```
**以前 (y0-y2) と書いていて裏表を取り違えていた。要修正。**

### 1.3 面の色 (`demo_glz` = 小さい方)
- hidden: 色 = `(base & 2) ? 4 : 0`。スロットを解放する。
- visible:
  - `shade = clamp(|cross| >> 7, 0, 63)` (lightshift=10 のときは >>8 相当 + 1.5 倍)
  - `slot = rolcol[base]`。無ければ 2,4,...,0x1e から空きを確保。
  - `slot<<3` の 16 エントリに
    `entry[i] = tint + backpal[i]/4` を書く。
    tint は `base & 2` なら `(R=cl, G=shade/2, B=shade)`、そうでなければ灰。
    ここで **`cl` は設定されない** (直前の `_lightshift` 由来の 7 か 10)。
    これが「青」の理由。
  - 塗り値 = `slot << 3`。

### 1.4 面の色 (`demo_glz2` = 大きい方)
- hidden: 色ワードの下位バイトそのまま (base = 2 か 4)。
- visible: `(base >> 1) & 1` → **0 か 1**。
- **パレットは書かない** → 背景パレット (0..15) を使う。

### 1.5 塗り (NEW.ASM)
- `__newgroup(1)`: 各面の辺を `{Y1,Y2,X,DX,COLOR}` として登録。
  同じ辺 (Y2/X/DX 一致) があれば **色を XOR して新規登録しない**
  (`xor cs:[si+NE_COLOR],al`) → 面の境界線が消える。
- `__newgroup(2)` → `ng_pass2`: 走査線ごとに x でソートしたスパン表
  `(x, color)` を作る。同じ x の辺は色を XOR して 1 本にまとめる。
  前フレームのスパン表とマージする (ダブルバッファ)。
- `ng_pass3` の `fillmacro`:
```
mov ah, al
or  ah, fs:[di]      ; fs = _bgpic
mov es:[di], ah      ; REPLACE (XOR ではない)
```
  `al` は「通過した辺の色の XOR 累積」。
  → `pixel = (囲んでいる面の色の XOR) | bgpic[pixel]`

### 1.6 パレットのタイムライン (MAIN.C 538-590)
- frame 700-764: `pal = backpal * (764-frame)/64` (フェードアウト)
- 765-789: ワイプ。`bgpic` の `y = 150 + (frame-765)*2` の 2 行を 0 に。
  frame > 785 で赤パレットを生成:
  `r = (a&1)*10 + (a&2)*30 + (a&4)*20 + (a&8)*16` など (a=0..15)。
- 790 以降: `pal = backpal` (赤)
- 2069 以降: フェードアウト

### 1.7 背景 (`bgpic`)
- 冒頭のズーム (MAIN.C 320-351) の結果が `bgpic`。
  `y1 = 130 + y/2`, `y2 = 130 + y*3/2`、`b = 25600/(y2-y1)` で
  fc 画像の 0..99 行を縦引き伸ばし、100..107 行の帯を下に付ける。
  シミュレーション結果: **188 フレームで y1=153, y2=200 に収束**。
  → チェック柄の床は画面最下部 (153..199) にだけ残る。

## 3. 修正したバグ (4 件 + 今回見つかった 4 件)

1. **`74a763c` 有効辺が 2 本未満の行で x を進め忘れ**
   `group_draw` の `if (nl < 2) continue;` の前に、辺の `x += dx` を行う。
   → 適用済み。
2. **`a4a0b92` 投影座標のクランプ ±2000**
   ±32000 に緩める (多角形が歪んで面が欠ける)。
   → 適用済み。ただし座標差が 64000 まで出るので、`edge_dx` /
   `cross3` は u32 / 飽和演算に直した (s32 の `<<16` であふれていた)。
3. **`02c3f2c` 1 行の有効辺リストが 64 本で打ち切り**
   `list[64]` → `list[MAXEDGE]`、`nl < 64` の条件を撤廃。
   → 適用済み (`MAXEDGE=512`)。
4. **`d05bed3` `checkhiddenbx` の式** (1.2 参照) — `y0-y1` に直す。
   → 適用済み。
5. **スパン塗りの y 座標系がずれていた** (今回発見)
   `group_draw` が `yy = y - GY` (0..199) を作り、辺の `y1/y2`
   (chunky 座標 28..227) と比べていた。→ 28 行ずれ、辺が本来より
   28 行遅れて有効になり、x も 28 行ぶん遅れていた。
   `y` と直接比べるように修正。
6. **画面の上端より上で始まる辺の x を進めていなかった** (今回発見)
   辺の `y1 < GY` のとき、`x` を `GY` の位置まで進めてから登録する
   (`add_sat` / `mul_sat` で飽和)。`fill_poly` (診断用) も同様。
7. **パレットのフェードアウトが動いていなかった** (今回発見)
   `palette_step()` が `if (frame > 800)` の else 側にあり、801 以降
   呼ばれていなかった。オリジナルどおり if の外へ出した。
   実測: frame 2060 は R199、2100 は R101、2150 は黒 (全画面 0)。
8. **小さい方のパレットが終了フェードに追従していなかった** (今回発見)
   小の visible パレット (slot<<3, 16 番以降) は `back6` から直接
   書いており、`pal6` のフェードが掛かっていなかった。
   `fade16` (0..64) を追加し、大と同じ係数でスケールするようにした。
   これで終了間際は両方の物体が同じように暗くなる。

## 4. 問題と現状

### 4.1 三角形 1 枚まるごと黒くなる — **解決済み**

原因は「色 0 の面」ではなく、**スパン塗りの被覆バグ**だった (3.5 / 3.6)。
- 修正前: 大だけを描くと、三角形の和 (全面を緑で塗った診断) より
  下側が 38px 短く、逆に外側へ 34k px はみ出していた。
- 修正後 (frame 1000, `DIAG=12` vs `13`):
  三角形の和 160280 px に対し通常描画 160278 px、一致率 99.8%。
  不一致は輪郭の 1〜2px の縁だけ。frame 1100 / 1300 / 1500 でも
  一致率 99.7% 以上を確認。
- 色 0 はオリジナルどおり残してある。閉曲面では表 (0/1) と裏 (2/4) が
  必ず重なるので、内部は 2/3/4/5 のいずれかになり黒くならない。
- 輪郭の 1〜2px の黒い縁は、**visible 0 の面が 1 枚だけ被覆する画素**で、
  オリジナルの `pixel = color | bgpic` から自然に出るもの。オリジナルには
  輪郭を補正する処理は無いので、**ポート側でも補正しない**ことにした。
  (1px を隣の色で塗る案も試したが、オリジナルに無い処理なので不採用。)
  消したい場合は色の割り当て側 (visible 0/1 を 1/1 にする等) で対処する。

### 4.2 大の赤の明るさ — **解決済み**

- 大きい方の面の色は 0/1 (visible) と 2/4 (hidden) の XOR なので、
  実際に使われるのは 2,3,4,5 番。
- オリジナルの式 `r=(a&1)*10+(a&2)*30+(a&4)*20+(a&8)*16` だと
  この 4 色が 8bit で 81/121/162/121 になり、参照の R 90..210 より
  暗く、2 と 5 が同じ値だった。
- **1..7 番だけ参照用の赤ランプに置き換えた** (このフェーズで 1..7 番を
  使うのは大きい赤の面だけ。0 番と 8..15 番は元の式のまま):

| index | 用途 | 6bit (r,g,b) | 8bit |
|---|---|---|---|
| 1 | 輪郭 (色 0 の単独被覆) | 15,3,3 | 60,12,12 |
| 2 | visible0 + hidden2 | 27,4,4 | 109,16,16 |
| 3 | visible1 + hidden2 | 37,5,5 | 150,20,20 |
| 4 | visible0 + hidden4 | 22,4,4 | 89,16,16 |
| 5 | visible1 + hidden4 | 49,6,6 | 199,24,24 |
| 6 | 4 面の重なり | 54,6,6 | 219,24,24 |
| 7 | 同上 (最大) | 59,7,7 | 239,28,28 |

- 実測 (frame 1000 / 1300, 大だけ): **R 89, 109, 150, 199**、
  G/B 16..24。参照の R 90..210, G/B 10..30 にほぼ一致。
- 小さい方のパレット (`back6[i]/4` を足す) も少し明るくなるが、
  重なりは引き続き小さい方のパレットのまま (半透明は維持)。

## 7. 性能 (2 物体時の低下対策)

- **アクティブ辺表**: 走査線ごとに全辺 (最大 144 本) を走査するのを
  やめ、辺を y1 でバケットに入れて行ごとに追加、y2 で削除する。
- **共有辺の O(1) 化**: 座標比較の O(n²) をやめ、頂点ペア (14x14) の
  表で引く。オブジェクトごとに表をリセットする (小と大で index が
  同じでも混ざらない)。
- **背景の 0 埋め**: ワイプ後は `bgpic` が全 0 なので、復元を
  `bgpic` からのコピーではなく 32bit の 0 埋めにする (`bg_zero`)。
- 計測: `M2_GLENZ_DIAG=64` で左上に「1 描画あたりの VBL×4」を
  緑のバーで出す (4 = 50fps, 8 = 25fps)。
  WinUAE 実測: 小だけの場面も 2 物体の場面も **4 (50fps)**。
- 出力は最適化前と同一 (frame 1000 の `DIAG=12` vs `13` で
  一致率 99.77%、黒 364 px)。
